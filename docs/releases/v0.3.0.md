# Canvas Guardian v0.3.0

> Release status: prepared, not yet tagged or published. Create the `v0.3.0` Git tag and GitHub Release only after the release-readiness pull request is merged and CI passes.

Canvas Guardian v0.3.0 is the first deliberately tracked modern release of the project. It keeps the existing self-hosted Guardian behavior while adding the Academic Data Pipeline, complete Canvas pagination, stronger runtime boundaries, and deterministic test coverage.

## Guardian runtime improvements

- Guardian assignment and announcement consumers now use complete paginated Canvas reads where full collections are required.
- Pending activity handling is consistent across activity monitoring, deadline reminders, and Telegram commands: only literal `excused === true` is treated as excused.
- Activity monitoring, announcement monitoring, deadline reminders, the Telegram bot, and Calendar sync are safe to import without starting services or opening the production runtime database.
- Deadline reminder thresholds remain unchanged but can now be tested against a fixed reference time.
- Shared runtime helpers keep pending/date rules, required environment validation, and Telegram HTTP behavior consistent without changing the command surface.

## Academic Data Pipeline

- Live Canvas assignments are combined with official offline Roll Call CSV exports.
- Roll Call is identified through Instructure external-tool metadata rather than its editable assignment name.
- Multiple attendance exports and courses are supported.
- Attendance rows are filtered to the authenticated Canvas user, validated, normalized, and deduplicated by Course ID, Section ID, and Class Date.
- The generated `data/output/academic-report.xlsx` contains Summary, Assignments, and Attendance sheets.
- Missing detailed attendance is left blank rather than inferred.

## Reliability and testing

The deterministic test suite covers Canvas HTTP behavior, pagination and same-origin protection, assignment normalization, attendance import and deduplication, workbook generation, Guardian pending/date rules, reminder thresholds, runtime configuration validation, Telegram HTTP behavior, and runtime import safety.

GitHub Actions runs `npm ci` followed by `npm test` for pull requests targeting `main` and pushes to `main`.

## Privacy and security

- Canvas and Telegram credentials stay in `.env`, which is ignored by Git.
- Google OAuth credentials and tokens remain under `secrets/` and are ignored.
- Local SQLite databases are ignored.
- Official attendance CSV exports and generated academic reports are ignored.
- Canvas pagination rejects foreign-origin continuation URLs before authenticated follow-up requests.

## Upgrade and setup notes

For an existing checkout:

1. Update to the released commit.
2. Run `npm ci`.
3. Keep your existing private `.env` and Google OAuth files; v0.3.0 introduces no new environment variables.
4. Confirm the variables required by the features you use are configured.
5. Use the supported npm runtime commands or the existing systemd deployment.

Supported runtime commands:

- `npm run guardian:activity`
- `npm run guardian:announcements`
- `npm run guardian:deadlines`
- `npm run guardian:telegram`
- `npm run guardian:calendar`
- `npm run academic:pipeline`
- `npm test`

## Known limitations

- Detailed Roll Call session attendance still requires official offline CSV exports; the tested Canvas APIs provide the aggregate Roll Call grade but not those class-date records.
- Deterministic automated tests do not replace live Canvas, Telegram, and Google Calendar smoke testing in the self-hosted environment.
- Deployment remains self-hosted and manually managed rather than distributed as a packaged installer.
- The `v0.3.0` tag and GitHub Release do not exist yet and should be created only from the exact merged `main` commit after CI is green.
