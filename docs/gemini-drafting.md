# Gemini drafting engine

`getAssignmentDraftContext(courseId, assignmentId, options)` in `src/assignment-draft-context.js` reads one explicitly selected assignment through the existing Canvas GET client. It returns the title, HTML description converted to text, submission types and allowed extensions, due date, available rubric criteria and points, and Canvas URL. Missing fields remain `null` or empty arrays. Canvas permissions still determine what the API returns.

`generateAssignmentDraft(context, { instructions, client, apiKey, model, timeoutMs })` and `reviseAssignmentDraft(context, draft, feedback, { client, apiKey, model, timeoutMs })` in `src/gemini-draft-engine.js` return `{ draft, explanation, gaps }`. Revision is stateless. `client` and `canvasRequest` options support isolated tests. Call these functions only after the user explicitly requests AI drafting for a selected assignment. No Telegram command is wired yet.

Configure `GEMINI_API_KEY` and optionally `GEMINI_MODEL` in the runtime environment. The default is the stable `gemini-3.8-flash`; it is never changed automatically if unavailable. The key's project must have Gemini API access and sufficient quota. Google AI Studio shows model availability and active limits. API keys created under current rules may be authorization keys; unrestricted standard keys are rejected. Paid tier setup requires Cloud Billing and may incur charges. The module uses low thinking for drafting, disables the SDK's default automatic continuation, and makes one bounded generation request per operation, with a 45-second timeout, a 4,096-token output limit, and explicit input size limits. Any response without a `STOP` finish reason, including `CONTINUATION` or `MAX_TOKENS`, is rejected instead of returning a partial draft. It returns sanitized error codes (`rate_limited`, `model_unavailable`, `timeout`, `invalid_response`, `api_rejected`, `api_failure`) for the caller to display or handle. It does not retry into another model.

Each explicit request sends the selected assignment context, optional instructions, and, for revision, the draft and feedback to Google. Canvas and Telegram credentials, unrelated records, and extra context properties are excluded. Google's [pricing and data-use table](https://ai.google.dev/gemini-api/docs/pricing) says free-tier content may be used to improve its products, while standard paid-tier content is not. Check the current terms and your institution's rules before sending course material. The model output is a working draft, not verified research; users must check facts, citations, and rubric fit. No Canvas upload, submission, or publication occurs.

Future Telegram integration should select an assignment first, call `getAssignmentDraftContext`, show the user the assignment and external sharing notice, then invoke generation only on their explicit `/draft` request. Hold the returned draft in the Telegram session for optional revision, passing the original context and user feedback to `reviseAssignmentDraft`. Handle `DraftError.code` with a user-friendly message. Any `/submit` workflow needs a separate implementation and review.
